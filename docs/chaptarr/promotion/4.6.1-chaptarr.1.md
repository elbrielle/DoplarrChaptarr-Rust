## Known issue found after publication (2026-08-29)

The published build does not configure a second format's author settings.
Chaptarr initializes them one format per add, so an author created by
`/request book` carries no audiobook quality profile, metadata profile, or
root — and an unconfigured format is a disabled one, whose searches the
server empties silently. In this build a later `/request audiobook` for
that author heals the settings only when it triggers an actual `POST /book`
(the server's own progressive fill). When the audiobook row already exists
no add fires, every monitor and edition read-back still passes, and the
acknowledged `BookSearch` can never return a release. The same build also
sends both formats' roots in existing-author add bodies, which the server's
progressive fill can route into the wrong format's root.

Neither is a regression from the Clojure bot and neither affects
single-format use, which is what the canary and the first production run
exercised. Fixed on `chaptarr-cross-format-settings` (author gate write
fills and verifies the requested format's settings, fail-closed; add bodies
carry only the requested format's root); the fix is fixture-proven only and
needs mutation case 13 live before the next release claims the sequential
cross-format path. Contract: `docs/chaptarr/COMPATIBILITY.md`, "Author
settings are per-format and lazily initialized".
