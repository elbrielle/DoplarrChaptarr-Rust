## Findings (each fixed at the root or recorded)

1. **Work-id normalization is id-space-wide, not a prefix flip.** Import maps
   the lookup's work id to a different canonical id with no shared sidecar
   (`gr:4836639` → `gr:100243626`; `gr:3234863` → `hc:69589`): the lookup id
   vanishes entirely — `goodreadsWorkId` carries the new id,
   `goodreadsBookId` is absent, `asin` populated only locally. No identity
   tier can bridge it, and the server's lookup rows for a not-yet-local work
   carry no association either. **Fix:** the `POST /book` 201 echo (the
   canonical row, idempotent for repeat adds) and the lookup row's
   local-book ids are treated as server authority beside the chain
   (`4ab3334`, `1a5ecaa`); the chain still governs unasserted rows.
2. **The original pipeline could never resolve a drifted new add** — it
   monitored the row via the add body then failed ("could not resolve … to a
   safe local book row"), leaving the checklist's partial state. Fixed by
   the echo resolution (`4ab3334`); the previously stranded request repaired
   and completed.
3. **`POST /book` can 500 *after* importing the catalog** ("Requested work …
   resolves to multiple local Audiobook books"). Recoverable: resolution
   continues against the just-imported rows through the identity chain
   (`1a5ecaa`).
4. **The lookup association appears once a work has local rows** and pointed
   at the correct drift-normalized row; distrusting it forced a re-add into
   server defects. Now trusted with format check, per-row state gate, and
   id-keyed read-back (`1a5ecaa`).
5. **Server defect:** the cross-format sibling mint can fail with a 409
   whose body is a bare error resource — `SQLite Error 19: NOT NULL
   constraint failed: Editions.Images`. Fail-closed on our side with the
   body's message surfaced; zero stray writes verified. Upstream-issue
   draft material.
6. **New-author imports ran synchronously inside `POST /book`** (every row
   stamped the same second; no `RefreshAuthor`/`RescanFolders` commands
   ever). The composite settle latch passed on its first look *correctly* —
   the handler had run before the add returned. The gate stays for the
   command-driven paths.
7. **Fresh-install seeding is two-layer** (migration 001 pre-seeds typed
   profiles; the event seeders only fill empty tables): the packet's
   "General-only fresh install" premise was corrected (`2b104f2`); the 2.7
   tiers are right in both worlds and the live `--check` proves the
   fresh-install path.
8. **A 202 pending add persists the author shell** (with gate flags from the
   add body) while the work stays pending; "nothing monitored or searched"
   holds, "nothing created" does not. A pending work can stay pending well
   past a few minutes (Pride and Prejudice remained pending through the
   run's end after the interrupted import).
9. **Operational notes:** `/command` history is short-lived (completed
   BookSearches age out within the run) — verification must snapshot
   immediately; idle chatter includes `RefreshMonitoredDownloads` /
   `ProcessMonitoredDownloads` roughly every 90 s and `DownloadAuthorMedia`
   after adds; lookup author-name variants can mint separate local authors
   ("Mary Shelley" vs "Mary Wollstonecraft Shelley"); pinning an edition
   rewrites the row's edition-derived title/ASIN; a zero-indexer BookSearch
   completes as a harmless no-op exactly as documented.
